기본 행동 16종, 추가 상호작용 11종, 시선 8방향과 대기 변형을 포함한 37개 클립을 완성했다. 클립별 원본 24fps 프레임 합계 6,801개를 투명 512px PNG 시퀀스와 256px 다중 페이지 아틀라스로 보존했다. [모션 검수 화면](http://127.0.0.1:8765/preview.html)에서 재생할 수 있다.

노트북 4종은 실제 대기 프레임을 시작·종료 이미지로 사용해 다시 제작했다. 서 있는 기본 자세에서 앉고, 가방에서 노트북을 꺼내 열고 작업을 시작하는 전환을 포함했다. 편안하게 다리를 접고 무릎 위의 아이보리색 노트북을 쓰는 자세를 채택했다. 같은 테이크에서 호출·휴식·정리와 기본 자세 복귀를 이어갔고, 고정 배율과 고정 색 보정을 모든 프레임에 공유한다.

모든 생성 요청에 MCP 무료 이벤트의 Unlimited 모드를 사용했다. 기준 이미지는 GPT Image 2.6과 Nano Banana 계열, 영상은 Seedance 2.5를 사용했다. 실제 요청과 결과는 [생성 작업 기록](production/higgsfield-jobs.json), 동작 지시는 [모션 제작 목록](production/motion-briefs.json), 연속 테이크와 채택한 구간은 [테이크 구성](production/motion-takes.json)에 보관한다.

투명 경계, 프레임별 시간표, 반복·복귀 구간과 별도 미리보기의 재생을 검수했다. DAP 본체의 로더 확장, 실제 이벤트 연결과 화면 이동 중 발 접지는 통합 단계의 작업으로 남아 있다.

코랄색 단발, 커서 머리핀, 남색 재킷, 폴더 모양 가방을 가진 꼬마 조수를 DAP의 고프레임 데스크톱 동료로 제작한다. 사용자의 말을 듣고, 작업을 기억하며, 결과를 가져오고, 기다릴 때는 조용히 곁에 있는 성격을 움직임으로 표현한다.

기준 콘셉트는 [캐릭터 콘셉트 원본](reference/dap-assistant-concept-v1.png)에 보관한다. 제작한 에셋의 실제 프레임과 재생 구간은 각 clip.json에 기록했다. 본체 연결에 관한 절은 구현을 위한 설계다.

## 참고 사이트에서 가져올 움직임 구성

CZN Animation Viewer의 Nia Portrait와 Model 프리뷰를 직접 확인했다. Portrait에는 idle과 touch가 있고, Model에는 attack_ready, attack_play1, attack_end, idle_to_b_idle, b_idle_to_idle, move, stop 등이 있다. Nia Model의 선택 목록에는 43개 애니메이션이 표시됐다. move는 약 1.1초, stop은 약 1.3초, idle_to_b_idle은 약 0.3초로 표시됐다. 이 길이는 해당 캐릭터에서 관찰한 값이다.

| 참고한 구성 | DAP에서 적용할 방식 |
|---|---|
| ready → play → end | 요청을 알아차림 → 작업 반복 → 결과를 정리하고 복귀 |
| idle ↔ b_idle | 편안한 대기 자세와 집중 자세 사이의 짧은 연결 |
| move와 stop 분리 | 출발, 제자리 보행 루프, 감속과 발 정돈 |
| idle과 touch 분리 | 평소의 잔잔한 움직임과 사용자에게 보내는 짧은 반응 |
| 머리·옷·소품의 후속 움직임 | 고개와 몸이 먼저 움직이고 머리카락·소매·가방이 뒤따르는 연기 |

참고 사이트는 Spine 3.8 WebGL 런타임을 사용한다. 힉스필드 영상에서 얻는 결과물은 연속 영상이므로, DAP용으로는 투명 프레임과 재생 시간표를 제작한다. 실시간 시선·입 모양을 본 리깅으로 제어하는 단계에는 파츠 분리와 리깅 공정이 추가된다.

참고 원본은 [Nia 전신 모션](https://bennosleep.github.io/czn-animation-viewer/viewer.html?m=rigs/model_1003), [Nia Portrait](https://bennosleep.github.io/czn-animation-viewer/viewer.html?m=rigs/portrait_1003), [뷰어 기술 설명](https://github.com/BenNoSleep/czn-animation-viewer)에서 볼 수 있다.

## 캐릭터 제작 기준

콘셉트 시트의 큰 전신 그림을 기준으로 정면, 좌우 3/4, 좌우 측면, 후면과 표정 기준을 만든다. 영상 생성에는 한 장에 한 캐릭터가 있는 기준 이미지를 투입한다.

- 커서 머리핀은 캐릭터 자신의 왼쪽 관자에 고정한다.
- 가방은 캐릭터 자신의 오른쪽 골반에 두고, 끈의 출발점과 가방 탭 방향을 통일한다.
- 남색 재킷, 아이보리 칼라와 반바지, 코랄 단발, 초록 눈, 청록 가방, 작은 금색 단추를 유지한다.
- 머리 크기, 눈 간격, 부츠 크기와 가방 부피를 정면·측면 기준에 기록한다.
- 손은 작은 면적에서도 읽히는 단순한 형태로 정리하고, 메모를 잡는 손 모양을 별도로 확보한다.
- 걷기는 좌우 방향을 각각 제작해 비대칭 액세서리의 위치를 일관되게 유지한다.

기준 이미지 세트에는 전신 자세, 표정, 가방의 닫힘·열림과 메모를 꺼낸 상태를 포함한다. 기준 이미지의 비율과 액세서리 위치를 확인한 뒤 Higgsfield Reference Element로 등록해 지원이 확인된 모델에서 재사용한다. Seedance 2.5에는 카탈로그에서 확인한 이미지 참조 입력을 사용한다.

### 음악 재생 신호와 연기

현재 DAP는 시스템 출력 오디오를 감지하고 `petEngine.onAudio(true)`로 dance 상태에 진입한다. `onAudio(false)`는 dance를 종료하고 호스트의 이전 상태나 대기 상태로 복귀한다. 감지 대상에는 음악·영상·통화 소리가 포함된다. [오디오 감지](C:/Users/dudal/project/dap-merge-check2/app/electron/main/src/audio-monitor.ts), [재생 신호 연결](C:/Users/dudal/project/dap-merge-check2/app/electron/main/src/pet-engine.ts)

음악 반응은 조용한 감상과 신나는 춤 두 가지로 제공한다. `music-playing`의 기본 에셋은 `music-listening`이며, 편안한 눈 감기와 미소, 느린 고개·어깨 박자로 음악을 즐기는 느낌을 표현한다. `dance`는 고개 끄덕임·어깨 반동·탄력 있는 무릎·좌우 스텝과 작은 점프를 같은 박자로 이어간다. 음악을 알아차리는 준비를 한 번 재생하고 감상 또는 춤의 반복을 유지한다. 일시정지·종료 신호에서는 움직임을 마무리하고 중립 자세로 정리한 뒤 호스트의 다음 상태로 연결한다. 머리카락·소매·가방은 몸보다 조금 늦게 따라 움직인다.

신나는 춤은 16초의 독립 테이크로 확보했다. 조용한 음악 감상과 혼자 균형을 잡으며 노는 모습은 24초 테이크에 각 12초씩 배치한다. 일하는 모습은 메모를 읽기, 손끝으로 짚어 검토하기, 완료한 결과를 보여주기로 구성한다. 가방과 메모가 상호작용하는 여섯 행동은 손이 종이 가장자리를 잡고, 같은 크기의 메모를 슬롯에서 들어 올리고, 다시 정렬해 넣는 접촉 동작을 중심으로 재제작했다. 세 행동씩 각 10초를 배치한다. 메모를 든 기준 이미지에서 손의 잡는 위치, 메모 치수와 비어 있는 슬롯을 먼저 확인한다. 좌우 걷기는 방향당 12초의 독립 구간으로 확보했다. 실제 음악 신호 연결과 상태 전환 검수는 본체 통합 단계에서 수행한다.

| 대화를 열거나 부름 | 사용자를 향해 고개를 들고 짧게 인사 | 채팅 열기 완료, 호출 또는 도착 이벤트 |
| 사용자가 말함 | 몸을 살짝 앞으로 기울이고 가끔 끄덕임 | 실제 음성 listening 상태 또는 명시적인 입력 상태 |

| 취소 또는 중단 | 하던 동작을 멈추고 메모를 가방에 넣어 복귀 | 해당 작업의 취소 확정 또는 중단 결과 |
| 이전 작업 이어가기 | 가방에서 이전 메모를 꺼내 가리킨 뒤 작업 자세로 이동 | 실제 작업 재개와 관련 결과물 선택 이벤트 |
| 노트북 작업 중 부름 | 현재 키 입력을 마치고 손을 멈춤 → 눈과 고개를 사용자에게 돌림 → 다시 타이핑 | 작업 중 호출·대화 열기와 해제 |
| 오래 작업한 뒤 휴식 | 손을 허벅지에 두고 가슴을 펴며 어깨와 목을 작게 풀기 → 키보드로 복귀 | 장시간 작업의 낮은 우선순위 휴식 |
| 노트북 작업 마무리 | 힌지를 따라 덮개를 닫음 → 같은 가방에 넣음 → 균형을 잡으며 다리를 풀고 기본 서기로 복귀 | 작업 종료 후 정리 상태 |

노트북 장면은 실제 대기의 시작·종료 자세를 공유하는 30초 테이크다. 기본 작업 클립은 공통 원본 0~720번 721프레임을 보존한다. 준비는 0~152번, 타이핑 반복은 153~322번, 정리하고 일어서는 복귀는 552~720번이다. 호출 반응은 336~431번 96프레임, 목·어깨 풀기는 432~551번 120프레임, 정리와 복귀는 552~720번 169프레임으로 별도 제공한다. 이번 네 동작의 재생은 정방향이다.

앉는 과정은 짧은 무릎을 굽히고 손으로 균형을 잡은 뒤 다리를 편안하게 접는 중간 자세를 보여준다. 원래 머리와 팔다리 길이를 공유하고 영상 전체에 같은 캔버스 좌표와 고정 배율을 적용한다. 대기의 실제 프레임과 시작 자세를 비교해 구한 고정 RGB 보정도 전체 테이크에 공유한다. 노트북을 닫고 가방에 넣은 뒤 다리를 풀고 일어서는 연결까지 기본 작업의 복귀에 포함했다. 마우스 시선과 상태별 중단·복귀의 실제 이벤트는 본체 연결 단계에서 검수한다.

일반 답변 완료는 답변 제스처의 마무리에 연결한다. 작업 성공 연기는 실행 결과와 산출물 준비가 확인된 경우에 연결한다. 진행 중인 도구가 여러 개면 해당 작업의 집계 상태로 작업 자세를 유지한다.

## 360도 시선 추적

마우스가 있는 방향을 눈과 고개로 따라보는 연기를 추가한다. 정면 자세에서 화면 기준 오른쪽, 오른쪽 아래, 아래, 왼쪽 아래, 왼쪽, 왼쪽 위, 위, 오른쪽 위의 8방향을 각각 제작한다. 각 방향은 중립에서 시선을 옮기는 준비, 응시 반복, 중립 복귀로 구성하며 원본 24fps 프레임을 유지한다.

시선이 먼저 움직이고 고개가 조금 늦게 따라간다. 몸통과 발은 정면에 둔다. 방향별로 동공과 턱의 각도를 구분하고, 대각선에서는 수평·수직 변화를 함께 표현한다. 같은 방향을 보는 동안에는 작은 호흡을 유지한다.

화면 좌표의 오른쪽을 0도로 두고 시계 방향으로 45도씩 배치한다. 방향 전환은 복귀와 다음 준비를 연결하고, 경계 부근의 잦은 교대는 호스트에서 히스테리시스로 다룬다. 시선 이벤트의 우선순위와 마우스 좌표 연결은 본체 통합에서 검수한다. 제작 범위는 기본 16종과 상호작용 11종에 시선 8방향을 더한 구성이다.

## 동작의 자연스러움을 만드는 재생 규칙

좌우 걷기의 방향 전환은 시선과 고개가 먼저 향하고, 한 발에 체중을 싣고 다른 발을 들어 새 방향으로 디딘 뒤 골반과 상체가 따라가는 순서로 제작한다. 중간에 무릎이 굽혀진 비대칭 3/4 자세를 지나 첫걸음으로 이어진다. 멈출 때도 한 발을 지지하고 다른 발을 모으며 골반과 어깨가 정면으로 돌아온다. 본체에서는 전환의 첫 접지와 이동 시작을 맞춰 발 미끄러짐을 검수한다.

### 시간과 몸의 움직임

- 기본 납품 목표는 24fps 수준의 연속 동작이다. 원본이 30fps이면 고유 프레임과 타임스탬프를 보존하고 클립별 시간표로 재생한다. 4초 동작은 24fps 기준 96프레임에 해당한다.
- 실제 생성 결과의 FPS, 프레임 중복과 움직임 변화를 검사해 납품 프레임을 정한다. 모델의 현재 파라미터에 없는 FPS 설정을 생성 API에 임의로 추가하지 않는다.
- 팔을 들기 전 어깨와 시선의 준비, 정지할 때 무게중심의 회복, 움직인 뒤 머리카락·소매·가방이 늦게 안정되는 구간을 넣는다.
- 걷기 루프는 캐릭터가 셀 안에서 제자리 보행하도록 만든다. 화면상의 이동은 DAP 엔진이 담당하고, 보폭의 주기와 실제 이동 속도를 맞춘다.
- 서기·앉기·잠듦·들림은 각자 기준 자세와 기준점을 가진다. 두 자세를 잇는 짧은 연결 클립을 사용한다.
- 루프의 마지막과 처음에서 위치·몸의 기울기·움직임 방향을 함께 맞춘다. 편집 시 연결부를 프레임 단위로 손본다.

### 이벤트와 중단

시각적 우선순위 초안은 드래그·직접 입력 → 승인·추가 질문 → 작업 결과·실행 → 대화 제스처 → 생활 대기다. 실제 작업 상태는 별도로 유지해 드래그를 끝낸 뒤 진행 중인 작업에 맞는 자세로 돌아가게 한다.

- 준비 구간은 해당 상태에 들어갈 때 한 번, 반복 구간은 상태가 유지되는 동안, 마무리는 상태가 끝날 때 재생한다.
- 스트리밍 청크가 올 때마다 인사·설명 동작이 처음부터 반복되는 현상을 막기 위해 턴 또는 실행 식별자로 시작을 구분한다.
- 취소·완료 뒤 늦게 도착한 이전 작업 이벤트는 실행 식별자와 현재 상태를 확인해 처리한다.
- 직접 입력과 드래그에는 빠르게 반응한다. 생활 동작은 사용자의 작업을 방해하지 않는 빈도로 배치한다.
- 작업 중 잠깐의 클릭이나 드래그가 발생하면 현재 작업의 최신 의미 상태로 복귀한다.
- 입 모양은 텍스트 설명 제스처와 실제 음성 재생에 맞춘 말하기를 구별해 제작한다. 실제 음성이 있는 경우 음성 타이밍을 사용한다.

대표 흐름은 대기 → 요청 확인 → 생각 또는 작업 준비 → 작업 반복 → 결과 확인 → 메모 전달 → 대기다. 승인 요청이 생기면 승인 대기로 연결하고, 해결된 결과에 따라 재개·취소 동작으로 이동한다.

## 힉스필드 제작 방식과 모델 파일럿

### 공통 제작 과정

1. 단일 캐릭터 기준 이미지와 정면·측면·표정 기준을 준비한다.
2. Higgsfield 미디어 라이브러리에 입력을 등록하고 Reference Element를 만든다.
3. 각 모션의 시작 자세, 핵심 자세, 종료 자세와 시간을 정한다.
4. 고정 카메라의 한 테이크로 모션을 생성한다. 준비·반복·마무리를 이어서 연기한 테이크는 편집에서 구간으로 나눈다.
5. 움직임과 캐릭터 일관성을 검수한 뒤 프레임을 추출하고 시간적으로 일관된 배경 매팅을 수행한다.
6. 발·가방의 기준점, 프레임 크기와 투명 경계를 정렬한다.
7. 별도 미리보기에서 클립과 재생 메타데이터를 검수하고, 본체 통합에서 이벤트와 화면 이동을 확인한다.

기본 입력은 정사각형 전신, 고정 카메라, 변하지 않는 조명과 단색 배경이다. 무료 이벤트의 720p 옵션으로 생성한 1:1 원본은 현재 960×960, 24fps로 완성됐다. 배경은 마젠타를 사용하고, 영상 생성 뒤 매팅과 경계 정리를 수행해 512px 투명 PNG와 256px 재생용 아틀라스를 만든다.

### 제작에 사용한 모델

| 모델 | 제작 역할 | 확인한 기능 |
|---|---|---|
| GPT Image 2.6 | 전신과 방향 기준 이미지 | 참조 이미지, 2k medium, 투명 PNG |
| Nano Banana 계열 | 방향 이미지와 머리핀 가림 관계 보정 | 참조 이미지, 1k, 마젠타 배경 |
| Seedance 2.5 | 기본 모션과 조수 상호작용 | omni_reference, 시작·종료 이미지와 참조 입력, 4~30초, 음성 off |

완성된 대기·생각하기 파일럿에서 형태 유지와 매팅을 확인했고, 인사·경청·수락·되묻기의 24초 테이크에서 행동별 분리도 확인했다. 후속 테이크는 같은 모델과 공통 중립 자세를 기준으로 제작한다. 얼굴·손·가방의 일관성, 발 접지, 움직임의 리듬과 반복 경계를 각각 검수한다.

Seedance 2.5에는 omni_reference 설정을 사용한다. Higgsfield Reference Element에는 DAP Assistant를 등록했으며, 영상 생성에는 확인된 이미지 참조와 시작·종료 이미지 입력을 사용한다. 손이나 가방의 연기가 반복해서 어긋나는 동작은 직접 연기한 영상이나 애니매틱을 준비해 Genjutsu로 수정하는 방법을 검토한다.

모델 사용법은 [Higgsfield Seedance 가이드](https://higgsfield.ai/creator-hub/help-center/ai-models/how-do-i-use-seedance), [Genjutsu 가이드](https://higgsfield.ai/creator-hub/help-center/tools/how-do-i-use-genjutsu)와 2026-11-15 연결된 모델 카탈로그를 기준으로 정리했다.

### 무료 이벤트 적용 확인

모든 이미지와 영상 요청에 use_unlim=true를 사용한다. 계정에서 확인한 이벤트 만료는 2026-11-16 07시 12분 KST다. 2026-11-15 05시 06분 KST의 잔액 재확인에서 제작 전과 같은 10크레딧을 확인했다. 작업별 요청 모델, 실제 결과 모델, 프롬프트와 상태는 생성 작업 기록에 남긴다.

## DAP용 납품 형식과 재생 확장

원본은 생성 영상과 기준 이미지를 보관하고, 가공본은 RGBA PNG 시퀀스와 모션별 시간표로 만든다. 최종 앱용은 시퀀스 또는 여러 페이지의 아틀라스로 납품한다.

- 마스터 기준 이미지는 1024px급, 런타임 이미지는 256px급과 고밀도 화면용 512px급을 후보로 비교한다.
- 프레임마다 같은 크기의 캔버스와 명시적인 발·몸 기준점을 사용한다. 앉기·수면·드래그는 자세에 맞는 별도 기준점을 둔다.
- 재생 메타데이터에는 캐릭터, 클립, 프레임 위치와 시간, 준비·루프·마무리 구간, 진입·종료 자세, 중단 가능한 지점을 기록한다.
- 2048px 아틀라스의 256px 셀은 한 페이지에 64프레임을 담을 수 있다. 필요한 클립은 여러 페이지로 이어서 기록한다. 페이지의 행·열 수와 클립의 총 프레임 수를 독립적으로 관리한다.
- RGBA 계산상 2048 × 2048 한 페이지는 디코딩 후 약 16MiB다. 현재 동작과 가까운 다음 동작을 우선 로드하고, 실제 메모리와 프레임 지연은 앱에서 측정한다.
- 자연스러운 손그림 에셋에 맞는 이미지 보간을 적용한다. 현재 스킨 캔버스의 imageSmoothingEnabled=false 설정도 실제 크기에서 비교한다.

본체 확장에서는 기존 프레임 배열·경과 시간 재생 로직을 재사용하고, 자산 경로와 시간표를 활성 캐릭터별로 선택하게 한다. 고양이 전용 고정 시간표는 캐릭터 메타데이터와 연결한다. 단발 동작의 종료도 선택한 클립 길이에 맞춘다. 기존 스킨의 등록과 재생 경로를 보존하면서 고프레임 팩용 버전 계약을 추가한다.

새 행동 키, 완료·승인·추가 질문 이벤트, 턴별 제스처, 전환과 복귀 처리는 본체 연결 작업에 포함한다. 파일 존재와 이벤트 선언을 각각 실제 호출·표시까지 검증한다.

## 제작 순서와 통합 기준

| 단계 | 결과물 | 확인할 내용 |
|---|---|---|
| 1 캐릭터 기준 정리 | 단일 전신·좌우 방향·표정·가방 기준 이미지와 Reference Element | 얼굴·비율·액세서리 방향 일치 |
| 2 모션 파일럿 | 대기·생각하기와 네 가지 상호작용의 투명 프레임 | 일관성·발 접지·행동 분리·루프·매팅 |
| 3 재생 경로 확인 | 대기 → 생각 → 짧은 사용자 반응 → 대기의 앱 내 시연 | 충분한 프레임, 발 기준점, 크기 변경과 중단·복귀 |
| 4 기본 팩 완성 | 16종 행동의 전체 프레임과 준비·반복·마무리 구간 | 현재 모션 대응과 좌우 이동, 수면·춤·음악 감상·노트북 작업·드래그·혼자 놀기 연결 |
| 5 조수 상호작용 | 추가 11종 행동과 자세 연결 | 대화·승인·추가 질문·취소·재개·작업 중 호출·휴식·정리의 실제 이벤트 대응 |
| 6 통합 검수 | 캐릭터 팩, 클립 메타데이터, 미리보기와 배포본 | 전체 사용 흐름과 자원 사용 검수 |

화면 검수는 기본 130px와 크기 설정의 작은 값·큰 값, 밝고 어두운 배경에서 수행한다. 손가락·머리핀·끈·가방의 형태, 투명 경계의 깜빡임, 발 미끄러짐과 반복 경계를 확인한다. 머리카락과 가방의 지연 움직임이 몸의 기준점을 흔드는지도 확인한다.

기능 검수에는 이동 중 클릭, 음성 입력 시작·취소, 긴 작업 중 승인 요청, 여러 작업의 완료 순서 바뀜, 성공·실패·취소 직후 새 요청, 드래그 중 응답 완료, 수면 중 호출, 화면 가장자리와 배율 변경, 캐릭터 전환과 재시작 복원을 포함한다.

첫 제작 묶음은 캐릭터 기준 이미지와 대기·오른쪽 걷기·생각하기다. 이 세 동작으로 외형 일관성, 가방과 옷의 후속 움직임, 반복 연결, 투명 가공과 DAP 재생을 한 번에 검증하고 나머지 제작에 같은 기준을 적용한다.
